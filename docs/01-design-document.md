# 项目二：智能分诊Agent — 方案设计文档

> 本文档记录 FDE 五步方法论在医疗分诊项目中的应用全流程。
> 项目定位：用 AI 编排工具（Coze）构建一个合规、实用的智能分诊 Agent。

---

## 一、行业速学

### 1.1 医疗分诊AI行业现状（2025年）

**政策驱动**
- 国家卫健委等5部门印发《关于促进和规范"AI+医疗卫生"应用发展的实施意见》
- 明确支持智能预问诊、精准分诊导诊等应用
- 同时划定红线：AI不得替代医师诊疗、禁止AI自动生成处方

**市场规模**
- 2025年全球AI应用市场总值预计1270亿美元，医疗板块占约1/5
- 全国34省市近10000家医院已部署大模型驱动的智能导诊服务
- 腾讯觅影影像AI覆盖500余家机构，辅助近1000万人次检查

**标杆案例**
| 医院 | 应用 | 效果 |
|---|---|---|
| 阜外深圳医院 | 全流程智能导诊 | 门诊量+14.7%，候诊时间35→18分钟 |
| 某三甲医院 | AI分诊系统 | 准确率78%→94%，夜间值班医生工作量-65% |
| 华西医院 | "华西黉医"大模型 | 出院病历书写10分钟→2-3分钟 |
| 微软 MAI-DxO | AI诊断工具 | 304个病例测试准确率85.5%，超21位资深医生 |

### 1.2 行业痛点

| 痛点 | 现状数据 | AI可创造价值 |
|---|---|---|
| 挂号难 | 患者挂错率20-30% | 症状→科室精准匹配 |
| 导诊台压力大 | 三甲医院导诊日均300+人次 | 7×24小时AI分诊 |
| 急诊资源错配 | 非急症占急诊40% | 紧急程度自动评估 |
| 夜间无人导诊 | 基层医院普遍无夜间导诊 | 全天候在线服务 |
| 数据孤岛 | 医院系统标准不一 | AI可跨系统检索 |

### 1.3 监管红线

- 《互联网诊疗监管细则》：AI不得替代医师本人提供诊疗服务
- 湖南省医保局/北京市：禁止AI自动生成处方
- AI医疗应始终定位于医生的辅助工具

## 二、痛点定位

### 2.1 核心问题

患者在就医流程的第一步——"我该挂什么科"——就面临困难：
1. **信息不对称**：患者不了解医院科室划分逻辑
2. **症状描述不准**：患者用非标准语言描述症状，难以匹配科室
3. **紧急程度不明**：患者无法判断症状是否需要急诊
4. **时间成本高**：导诊台排队、挂错号重新排队

### 2.2 AI价值切入点

选择"分诊推荐"作为切入点，而非"诊断"或"治疗"：
- **合规**：分诊推荐属于信息服务，不涉及诊疗行为
- **价值**：解决患者最前端的痛点（不知道挂什么科）
- **可行性**：症状→科室映射有明确规则，适合知识库+RAG
- **差异化**：加入紧急程度评估，比传统挂号系统更有价值

## 三、方案设计

### 3.1 产品定位

**智能分诊推荐助手**（非诊断工具）

核心功能：
1. 症状采集（多轮对话收集患者症状）
2. 紧急程度评估（红/黄/绿三级预警）
3. 科室推荐（精准匹配就诊科室）
4. 就诊建议（含就诊前准备和免责声明）
5. 健康科普（疾病知识宣教）

不做的事：
- 不做诊断
- 不开处方
- 不推荐用药
- 不替代医生面诊

### 3.2 技术架构

```
用户入口（网页/微信/飞书）
        ↓
Coze 智能分诊Bot（多轮对话引擎）
        ↓
工作流：症状采集 → 紧急评估 → 科室推荐 → 就诊建议
        ↑（知识库支撑）
        ├── 症状→科室映射库（90+症状，8大部位）
        ├── 紧急症状识别库（红/黄/绿三级）
        └── 常见疾病科普库（50+疾病）
        ↓
输出：分诊报告 + 科室推荐 + 就诊建议
```

### 3.3 工具选择

| 维度 | 项目一（管道腐蚀AI） | 项目二（智能分诊Agent） |
|---|---|---|
| 行业 | 能源/工业 | 医疗 |
| 构建工具 | Dify Cloud + Streamlit | Coze（扣子） |
| RAG方式 | Chatflow + 知识检索 | Bot + 知识库 |
| 部署方式 | Streamlit Community Cloud | Coze 网页发布 |
| 交互形式 | Web表单 + 问答 | 多轮对话Bot |
| 代码量 | Python ~700行 | 零代码 |

选择Coze的原因：
1. 与项目一的 Dify 形成工具栈对比，证明FDE工具通用性
2. 零代码构建，符合FDE"编排工具"理念
3. 自带发布渠道（网页/微信/飞书/API），无需额外部署
4. 国内访问无障碍，免费额度充足

### 3.4 知识库设计

三个知识库文件，均为 Markdown 格式：

1. **symptom_department_mapping.md**
   - 90+症状条目，按8大身体部位分类
   - 每个症状：推荐科室 + 可能疾病 + 紧急程度 + 就诊建议
   - 附科室反查索引

2. **emergency_symptoms.md**
   - 红/黄/绿三级分类
   - 红色：10大类危及生命的急症
   - 黄色：12类需24h内就诊的症状
   - 绿色：可常规就诊的症状
   - 紧急程度评估规则

3. **disease_encyclopedia.md**
   - 50+常见疾病科普
   - 每个疾病：简介 + 症状 + 科室 + 保健 + 就诊准备
   - 就诊前准备建议

## 四、合规设计

### 4.1 定位边界

- **可以做**：症状采集、科室推荐、紧急评估、健康科普
- **不可以做**：诊断疾病、开具处方、推荐用药、替代医生

### 4.2 免责声明

在所有分诊结果中嵌入免责声明：
- "本系统仅提供分诊推荐，不构成医疗诊断"
- "最终就诊科室以医生建议为准"
- "紧急情况请立即拨打120或前往急诊科"

### 4.3 安全机制

- 紧急症状识别 → 优先提示急诊
- 不回答"我得了什么病"类诊断问题
- 不推荐具体药物
- 对儿童/孕妇/老年人特殊人群加权评估
